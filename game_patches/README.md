# game_patches

ActionScript snippets that this project injects into *your* decompiled copy of
the game.

**No game source is redistributed here.** Everything in this directory is
original code written for this project, plus the scripts that insert it into
files you produced yourself by decompiling your own copy of the game. See
[`../NOTICE`](../NOTICE) for the licensing situation.

---

## What gets patched, and why

| Target | What is injected | Why |
|---|---|---|
| `GameCtrler.as` | the state bridge — writes a JSON snapshot of both fighters to disk every 2nd frame | **This is the observability layer.** Without it there is no AI. The injection code is generated by `../build_bridge.py` (see `../bridge/`). |
| `FighterMcCtrler.as` | `getActionCtrler()` accessor | The bridge needs a stable way to reach the per-fighter action controller from `FighterMain`. |
| `FighterTester.as` | the debug panel (mode, characters, assists, map, frame rate, HP regen) + an F1 hotkey + `bvnExportPanel()` | The stock test UI cannot select *vs-CPU* mode or read its own fields back. Without this, the Python side cannot verify what it typed before starting a match. |
| `GameStartCtrler.as` | a call to the existing `skip()` at the top of `renderStart1v1()` | Round start drops from 40–60 s to 1.9–4.2 s, which makes automated evaluation practical. |

## Usage

Decompile your own SWF first (any FFDec build with a CLI):

```bash
ffdec-cli -export script ./decompiled_main ./FighterTester.swf
```

Then:

```bash
# 1. The bridge (this one generates its own code, no snippet files needed)
python build_bridge.py

# 2. The debug panel
python game_patches/patch_debug_panel.py --src decompiled_main/scripts/FighterTester.as

# 3. The intro skip
python game_patches/patch_intro_skip.py

# 4. Rebuild and install
python build_debug.py
```

Every patcher:

* is **idempotent** — running it twice is a no-op;
* writes a `.orig` backup next to the file it modifies on first run;
* supports `--check` to report what it would do without writing;
* **refuses to guess**: if an anchor is missing or ambiguous, it tells you the
  file is probably from a different game version rather than producing a
  broken build.

## `panel/*.as`

The five snippets inserted into `FighterTester.as`, in order:

| File | Inserted after | Contents |
|---|---|---|
| `block1.as` | the last `import` | the extra imports the panel needs (`File`, `FileStream`, `FocusEvent`, …) |
| `block2.as` | `private var _p1InputId:TextField;` | the `_testMode` field and its documentation |
| `block3.as` | `buildTestUI();` | the `ENTER_FRAME` hook that calls `bvnExportPanel()` every 4 frames |
| `block4.as` | end of the previous method | the `bvnExportPanel()` method itself |
| `block5.as` | replaces `GameMode.currentMode = 40;` | uses `_testMode` instead of a hard-coded mode |

`intro_skip.as` is a single block: a comment banner, the `skip()` call, and an
end marker.

## If a patch does not apply

The anchors are ordinary lines from the game's own source. They can differ if
your copy of the game is a different version. The patcher prints the anchor it
could not find — send that along with your game version and it is a
five-minute fix.

You can also patch by hand: open the file, find the anchor line, and paste the
matching snippet directly beneath it (or, for `block5.as`, replace the line).
